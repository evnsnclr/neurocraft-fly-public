# Community code

Help people investigate the model and make the software usable. Be respectful
of different backgrounds and levels of experience, and focus criticism on
claims, evidence and code rather than the person making them.

We expect participants to:

- ask clear questions and make room for newcomers;
- distinguish observations from assumptions and correct mistakes openly;
- respect privacy, attribution and other people's time;
- disagree without insults, harassment, threats or discriminatory treatment;
- avoid sexualized content and unwanted personal contact;
- avoid publishing another person's private information or correspondence.

This applies to project issues, pull requests and other project-managed spaces.
Maintainers may edit or remove inappropriate content, lock a discussion, or
restrict participation. Responses should be proportionate to the conduct and
its effect, with an explanation when sharing one does not expose private details.

## Raise a concern

A private community-report destination has not yet been established for this
alpha. Use **Issues → New issue → Private contact request** and state only that
you need a private conduct-report channel. Do not post names, accusations,
screenshots or other identifying details in that request. Wait for a private
destination before submitting the report; this repository does not claim that
GitHub issue comments are confidential.

For technical vulnerabilities, follow [SECURITY.md](SECURITY.md). Maintainers
must publish and verify the private contact process before opening broader
community support. This document does not promise continuous monitoring or an
emergency response service.
